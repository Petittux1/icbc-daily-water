# ICBC 浇水小助手（学习用）

一个 **KSU / Magisk** 模块：每日**第一次打开**工行 App 时，自动进入"热门任务"完成浇水领 i豆。
实现方式为 **纯 root 直控**（`screencap` 取屏 + 像素探针判定 + `sendevent` 注入触摸），**不使用**无障碍服务、Xposed、`input` 注入。

## 特性

- ✅ 每天只自动执行一次（`state.txt` 当日防重，成功即写回日期）
- ✅ 15 分钟冷却（防误触连续触发）+ 失败重试上限 3 次
- ✅ 像素投票判定首页（3 点橙色卡行 ≥2 命中），不依赖 UI 层级
- ✅ 广告过渡页快速防御（最多 2 次点击，不空等）
- ✅ 完成/失败震动提示（守护态下 `cmd notification` 会 Failed transaction，故用 sysfs 震动）
- ✅ 完整日志 `log.txt` 便于排查

## 原理

```
开机 → KSU/Magisk 拉起 service.sh 守护进程
     → 每 2s 轮询前台 App，连续两次确认是工行EC → 触发
     → water.sh: 读设备缓存(开机发现一次, 换机/重启自动重建) → 三点投票确认首页
       → 点"热门任务"入口 → 广告防御 → 下滑一屏 → 点"立即参与"
       → 蓝水壶页判定 → 点浇水
     → 成功: 写当日 state.txt + 震动 + 截图; 失败: 记 try.txt
```

从打开 App 到第一次点击"热门任务"入口约 **5 秒**（守护轮询+确认约 4s，其余是取屏判定）。

## 环境要求

- 已 root 的安卓设备（KSU 或 Magisk 均可），模块目录 `/data/adb/modules/`
- 目标 App 包名 `com.icbc`（如不同请改 `service.sh` 顶部 `PKG` 和 `water.sh` 中的启动命令）
- 分辨率与坐标需要按你的设备**校准**（见下）

## 安装

1. 将本目录放入设备 `/data/adb/modules/icbc_daily_water/`（zip 刷入亦可，含 `module.prop`）
2. 授予 root；重启手机生效
3. 查看日志：

```sh
tail -20 /data/adb/modules/icbc_daily_water/log.txt
```

测试（清掉今日防重后再打开 App 即可重跑）：

```sh
rm /data/adb/modules/icbc_daily_water/state.txt
```

## 校准（换设备必做）

所有设备相关参数集中在 `water.sh` 顶部"设备配置区"：

| 项 | 获取方法 |
|---|---|
| `D` 显示ID | `adb shell dumpsys display` 查 `mDisplayId`（多数手机为 0） |
| `SW × SH` 分辨率 | `adb shell wm size` |
| 坐标（入口/滑动/按钮/探针点） | `adb shell screencap /sdcard/s.png` 后 `python3 tools/px.py s.png x,y ...` 取色，按需修改 |

坐标含义（示例为 1220×2656）：
- `(606,1067)` 热门任务入口
- `(216,778)/(518,780)/(746,748)` 首页橙色卡行三点（R>200 且 90<G<190 且 B<140，≥2 命中即首页）
- `(1144,326)/(1172,326)` 广告过渡页快速点击点
- `(610,1900)→(610,900)` 下滑手势
- `(608,2138)` 立即参与按钮
- `(750,750)` 水壶点击点；`(750,746)` 浇水页判据（B>200 且 R<170 且 100<G<220）

## 日志解读

| 行 | 含义 |
|---|---|
| `SD_BOOT` | 守护进程启动（开机自启成功） |
| `TRIG` | 检测到工行前台，开始执行 |
| `VOTE=3` / `S1_HOME` | 首页三点投票通过 |
| `S2_ENTRY` / `S2_ADQ` | 点入口 / 广告防御点击 |
| `S3_SWIPE` / `S3_TAP` | 下滑 / 点立即参与 |
| `S4_WP` / `WATER_OK` | 蓝水壶页确认 / 浇水成功 |
| `FAILn` | 失败（n 为退出码），连续 3 次进 `try.txt` 阻塞当日 |
| `OK` | 当日执行成功 |

## 常见问题

- **想手动跑一遍完整水链看效果？** 先把工行切到首页，root 终端执行 `sh tools/run_once.sh`（或直接 `sh /data/adb/modules/icbc_daily_water/water.sh`），它会当场跑完整条链，不经过守护进程、不抢跑。
- **打开 App 时模块会不会和我的手打架？** 不会。触发后首页判定会先耐心等待（前两次探测不回退，给冷启动让路），确认是首页后才开始操作。
- **通知不出来？** 守护进程调用 `cmd notification` 会报 `Failed transaction`（binder 限制），模块改用震动提示；成功/失败都会震一下。
- **重启后没自动启动？** 确认模块已启用且 `log.txt` 有最新的 `SD_BOOT`。
- **失败排查？** 看 `log.txt` 里最近的 `DPX` 行与失败截图（`SNAP=1` 时输出到 `WORK` 目录）。
